# Memory Harness 产品交互、DIY 与自动沉淀规范

状态：开发前评审稿
日期：2026-08-21
依赖：[ADR-010](ADR-010-STRUCTURED-SEMANTIC-TEMPORAL-GRAPH.md)
本轮边界：定义交互和验收，不修改当前产品

## 1. 产品目标

Memory Harness 的默认体验必须让第一次使用的人在不理解插件、Pipeline、Schema 和图数据库的情况下完成四件事：

1. 导入一份文件、录音转写或对话；
2. 看见系统真正提取了什么，并知道“谁在何时何地做了什么”；
3. 检索、浏览、纠正并追溯到原始 Evidence；
4. 看见内容如何继续生长为项目状态、长期记忆和 Agent 能力资产。

开放和 DIY 是核心能力，但不以空白画布作为默认入口。系统先提供一套完整、可解释、可替换的默认策略，再让高级用户逐阶段替换插件、增加记忆类型、增加项目组件或新建流程。

## 2. 信息架构

### 2.1 默认导航

“开始使用”面向所有用户：

- 记忆总览：最近导入、待处理、重要变化、项目动态、能力资产候选；
- 导入记忆：文件/文件夹/文本/对话导入、项目归属、处理模式、进度与结果；
- 检索：混合检索、作用域、时间、实体和类型过滤；
- 记忆库：结构化知识、语义关系、时间演化、来源追溯；
- 项目工作台：项目上下文、目标、里程碑、决策、风险和可选组件；
- 待我审核：有歧义、受保护变化、冲突、合并和能力资产激活；
- 运行记录：每次沉淀的业务结果、过程、费用、错误和副作用。

“高级构建”默认折叠：

- 沉淀策略：自动/辅助/手动/计划任务以及项目级策略；
- 流程工坊：编辑 Pipeline、阶段和路由；
- 插件中心：安装、启停、配置、权限、版本和作用页面；
- 能力资产工厂：Prompt、Skill、Rule、Constraint、Procedure、MCP、Tool Recipe。

“设置”包括：

- 模型与 Agent；
- 权限与作用域；
- 健康、备份与恢复。

### 2.2 “收件箱”的产品语义

收件箱是未明确归属的全局暂存区，不是业务项目：

- 不在正常项目切换器里与“个人”“项目 A”并列；
- 出现在导入、待审核和总览的“待归档”区域；
- 可以批量归入个人或某个项目；
- 只有在高级设置中才能查看其内部系统 ID；
- 旧数据迁移时保留原作用域，不自动移动。

## 3. 记忆库

### 3.1 默认顺序

记忆库按以下顺序解释内容：

1. 本项目/个人空间当前有多少 Evidence、有效知识、事件、长期记忆、关系、时间事实和能力资产；
2. 哪些内容最近新增、更新、冲突或需要审核；
3. 结构化知识列表；
4. 语义关系图；
5. 时间线；
6. 来源沉淀链；
7. 插件贡献的扩展类型。

“插件对象”不再是一个只有数字的孤立页签。插件贡献的客户需求、商机、情景记忆、资产等对象分别进入与用户任务匹配的区域，同时保留“全部类型”目录供高级检查。

### 3.2 Knowledge Unit 列表与详情

列表每行至少显示：

- 类型：事实、事件、目标、决策、风险、程序等；
- 主体；
- 关系/动作；
- 对象或结果；
- 发生时间或“时间未确定”；
- 地点；
- 来源说话者；
- 置信度和质量状态；
- 项目/个人作用域；
- 原始 Evidence 入口。

禁止用“完整句子 + 百分比”代替全部结构。

点击后打开详情抽屉，包含：

1. 人可读的规范化陈述；
2. 主体、关系、对象、参与者角色、地点和时间；
3. “谁说的”与“说的是谁”的差异；
4. 原文短片段、上下文和位置；
5. 实体解析候选与理由；
6. 模型、插件、版本、Run 和时间；
7. 修订、合并、取代、冲突历史；
8. 纠正、拒绝、重新处理和查看邻居操作。

如果主体、时间或实体无法可靠确定，页面明确显示“未解析/有歧义”，并提供候选选择。禁止以 Owner 头像或“用户”作为缺省答案。

### 3.3 三种图必须分开

#### 语义关系图（默认）

- 节点是人、组织、项目、产品、地点、工具、概念和事件；
- 连线显示有方向的关系标签；
- 支持搜索、节点类型和关系类型过滤；
- 默认只显示选中节点的一跳邻居，可切换二跳；
- 选中节点高亮 incoming/outgoing，并在侧栏显示双向关系；
- 点击关系显示 Assertion、有效期、置信度和原始 Evidence；
- 支持表格/列表替代视图，保证大图和无障碍使用。

同一 Assertion 只存一次。反向显示由关系注册表生成，例如 `works_on / worked_on_by`，不是复制一条可独立修改的事实。

#### 时间线

- 以事件发生时间和事实有效期组织；
- 能切换“事件时间”“系统记录时间”“Evidence 捕获时间”；
- 显示 before、after、during、overlaps、causes、supersedes；
- 相对时间未解析时进入“待确认时间”，不会虚构日期；
- 支持 as-of 日期查看当时有效的事实。

#### 沉淀链路

- 展示 Evidence → Unit → Episode/Memory → Project/Asset；
- 默认围绕选中对象显示，不一次铺开全部对象；
- 每条线说明 extract、consolidate、project、materialize、supersede；
- 能从任意派生对象返回原始 Evidence。

当前六列扇形图迁移到此视图，并改名为“沉淀链路”。

### 3.4 图谱防止“毛线团”的规则

- 首屏节点不超过 80 个；
- 默认一跳，二跳按需加载；
- 相同类型/社区可折叠为簇；
- 标签只在选中或缩放到阈值后显示；
- 使用分页邻居请求，不为一个 Evidence 同时绘制上千条边；
- 允许保存过滤器和固定节点；
- 任何图都必须有列表视图和来源详情。

## 4. 导入与沉淀控制台

### 4.1 导入前

用户选择内容后只需要理解以下设置：

- 导入到：个人、已有项目、新项目或暂存收件箱；
- 处理模式：推荐的“辅助自动”、自动、仅保存原文、手动；
- 参与者：可选地为说话人 A/B 填姓名或保持未知；
- 时间锚点：录音/对话发生时间，默认使用文件或来源元数据；
- 隐私范围：Owner、指定 Agent、项目成员；
- 高级选项：使用哪套 Pipeline/插件组合，默认折叠。

### 4.2 导入后结果页

结果页不只显示“完成”，而显示：

- Evidence 已保存及哈希；
- 识别到的参与者、实体、事件、时间表达；
- 候选、接受、过滤、有歧义、需审核的 Knowledge Unit 数量；
- 新增、更新、合并、冲突、取代的记忆；
- 生成的项目卡片和能力资产候选；
- 每类被过滤内容的原因；
- 总耗时、模型、token/估算成本、失败或降级；
- “查看运行”“查看记忆”“处理待审核”入口。

### 4.3 自动化模式

每个项目可以选择：

| 模式 | 行为 |
| --- | --- |
| 自动 | 导入后执行已授权全部阶段；受保护变化仍进入审核 |
| 辅助自动（默认） | 运行提取和候选生成，歧义/冲突/资产激活等待审核 |
| 手动 | 只保存 Evidence，由用户启动全部或部分沉淀 |
| 计划任务 | 按时间批量处理，仍遵守权限和人工门 |

开关显示最后生效时间、作用范围和下一次运行，不能只是一个无说明的布尔值。

### 4.4 手动触发

在导入结果、记忆详情、项目工作台和沉淀策略页提供：

- 运行完整流程；
- Dry Run：只预览候选和副作用，不写入权威对象；
- 从某一步重新运行；
- 只重新处理选中的 Evidence、Unit、Entity、Project 或 Asset；
- 基于已有 Run 分支重跑；
- 取消尚未进入不可中断提交阶段的运行。

每次操作创建新 Run 和新修订，不覆盖历史。按钮旁明确显示预计会修改哪些对象、会否调用外部模型以及是否需要审核。

## 5. 项目工作台

### 5.1 默认模板

一个新项目默认包含：

- 核心上下文；
- 当前目标；
- 里程碑；
- 关键决策；
- 风险与待确认；
- 最近事件时间线；
- 相关人员/组织/工具；
- 关联 Evidence；
- 能力资产；
- 待审核变化。

这些卡片来自 Projection，不复制记忆正文。

### 5.2 摘要折叠规则

“自动沉淀摘要”首屏显示：

- 一句状态；
- 最多 3 条关键变化；
- 最多 320 个中文字符；
- 更新时间、来源数量和置信度；
- “展开详情”和“查看来源”。

展开后按目标、决策、进展、风险、人物、时间分节；长文本在抽屉或独立详情中呈现。不得再用 8000 字正文作为首屏卡片。

### 5.3 DIY 组件

用户在“添加组件”中看到按用途分组的目录：

- 核心项目：目标、里程碑、决策、风险、资金、事件；
- 业务：客户、需求、商机、竞争、经营指标；
- 研发：实验、论文、代码、缺陷、版本；
- 记忆：人物、关系、时间线、知识簇、Evidence；
- Agent：Prompt、Skill、Rule、Constraint、MCP、运行质量；
- 已安装插件贡献的其他组件。

每个组件说明数据来源、刷新方式、读写权限、空状态和对应插件。用户可以添加、隐藏、排序、调整尺寸、折叠和保存项目模板；普通 DIY 不需要编辑 JSON。

## 6. 能力资产工厂

### 6.1 入口与类型

“能力资产”不再只是一个计数。它有独立工作区，也可从相关 Knowledge Unit、Project 和 Run 进入。

顶部分为：Prompt、Skill、Rule、Constraint、Procedure、MCP、Tool Recipe。每类显示候选、待验证、待审核、已激活、已停用和新版本数量。

### 6.2 可见生长链

每个资产必须显示：

```text
来源记忆
 -> 类型识别
 -> 候选草稿
 -> 编译
 -> Lint / Fixture / Dry Run
 -> Owner 审核
 -> 激活版本
 -> 绑定 Agent / 项目
 -> 使用结果
 -> 下一版候选
```

用户可以查看每一步输入、输出、失败理由和 Diff；可以“继续编译”“验证”“提交审核”“激活”“回滚”“导出”。模型或插件不能自动扩大权限、安装 MCP 或激活受保护资产。

### 6.3 资产正文

- Prompt：正文、变量、适用时机、示例、版本；
- Skill：输入、输出、步骤、工具、约束、成功检查和 Fixture；
- Rule/Constraint：适用范围、例外、严重级别、冲突；
- Procedure：触发、负责人、步骤、结果；
- MCP：Server/Tool Manifest、连接、权限和危险操作；
- Tool Recipe：调用序列、前置条件、结果验证和回滚。

## 7. 插件中心与流程工坊

### 7.1 插件卡片必须回答六个问题

每张卡片显示：

1. 它解决什么问题；
2. 输入是什么；
3. 处理步骤是什么；
4. 输出什么对象；
5. 在哪些页面和项目生效；
6. 最近运行、对象数量、权限和健康状态。

使用 Surface 标签：记忆提取、语义图、时间线、项目工作台、能力资产、检索、运行记录。通用插件可以有多个标签。

### 7.2 配置体验

- 默认显示由 Schema 生成的表单、说明、推荐值和影响预览；
- 原始 JSON 只放在“高级编辑”；
- 启停前显示受影响的 Pipeline、页面和已有对象；
- 更新插件前显示版本变更、Schema 迁移和回滚点；
- 第三方插件显示签名/来源、权限和网络/文件访问；
- 没有对象时明确区分“尚未运行”“被过滤为零”“运行失败”“当前项目无数据”。

### 7.3 流程工坊

打开流程时先显示“这条流程服务于哪些入口和页面”，再显示画布。默认模板可以克隆，内置受保护版本不可直接改写。

节点详情至少包含：

- 用途与对应产品结果；
- 输入/输出 Schema；
- 插件与版本；
- 模型配置；
- 权限；
- 重试/超时；
- Fixture 与最近测试；
- 最近一次真实运行产物。

“发布”只创建不可变 Pipeline 版本；是否设为某项目默认流程是另一项显式操作。

## 8. 运行记录

### 8.1 首屏以结果为中心

每条 Run 首先显示：

- 处理了什么来源、属于哪个项目、由谁/什么触发；
- 成功、部分成功、等待审核、失败或取消；
- 新增/更新/合并/取代/冲突/过滤的对象数量；
- 实体、关系、时间事实、项目卡片和资产候选；
- 用时、模型、token/估算成本、重试和降级；
- 关键告警，例如“3 条主体不明确，未写入 Owner 记忆”。

### 8.2 阶段详情

每个阶段可展开：

- 输入对象和版本；
- 输出对象和版本；
- 过滤数量和 reason code；
- 创建、更新、删除/失效和副作用；
- 关键字段 Diff；
- Prompt/模型/插件版本和配置哈希；
- 开始/结束/耗时/重试；
- 权限判定；
- 错误、降级和人工门；
- 原始日志的受控入口。

Graph、Timeline、Effects 保留为技术视图，但位于“结果摘要”之后。图中节点直接显示业务名称和数量，例如“实体解析：12 个实体，2 个歧义”，不只显示 `transform.map`。

## 9. 性能与状态

- 记忆列表服务端分页，首屏不读取全部 Knowledge Unit；
- 图谱按邻居请求和簇加载，不下载全量图；
- 页面先显示骨架和已有统计，长查询分区加载；
- 切换页签取消过期请求，避免多个全量请求竞争；
- 计数与列表使用同一查询条件，避免“1172 但列表空”；
- 所有空状态区分无数据、待审核、未运行、被过滤、权限不足和加载失败；
- 后台重处理显示可恢复进度，不阻塞浏览；
- 重要列表支持键盘、焦点、屏幕阅读器和非图形替代视图。

## 10. 关键用户旅程验收

### 旅程 A：首次导入录音转写

1. 用户选择文件、个人空间和“辅助自动”；
2. 系统保存一份 Evidence；
3. 用户看到参与者与时间锚点；
4. 结果页显示接受、过滤、歧义和待审核数量；
5. Knowledge Unit 明确显示 source speaker 与 subject；
6. 语义图显示人/项目/地点及有标签关系；
7. 时间线显示可解析事件和待确认相对时间；
8. 任一结果可回到原文片段。

### 旅程 B：纠正错误主体

1. 用户打开一条有歧义 Unit；
2. 从候选实体中选择真实主体或新建实体；
3. 系统创建纠正修订和新的 reconcile Run；
4. 语义图、项目投影和检索更新；
5. 原错误不被删除，历史和原因可见。

### 旅程 C：从记忆形成 Skill

1. 多条程序/经验记忆产生 Skill candidate；
2. 资产工厂显示来源、输入、输出、步骤、约束和成功检查；
3. Fixture/Dry Run 给出结果；
4. Owner 审核后激活版本；
5. 绑定到指定 Agent/项目；
6. 后续真实使用结果进入下一版候选，但不自动覆盖当前激活版。

### 旅程 D：DIY 项目工作台

1. 用户从组件目录添加“商机”和“时间线”；
2. 页面说明对应插件、数据来源和权限；
3. 用户调整顺序、尺寸和折叠；
4. 刷新后布局保留；
5. 组件没有数据时说明是未运行、无匹配还是权限不足。

## 11. 本规范的完成定义

不能只以“页面存在”或“接口返回 200”验收。必须同时满足：

- 默认路径不需要进入高级构建即可导入、查看、检索、纠正和追溯；
- 高级构建中的每个插件/流程都能指出自己影响的前台页面和对象；
- 手动、自动和 Dry Run 都产生真实可解释 Run；
- 图、时间线、项目卡片和资产均来自同一权威对象链；
- 长文本有摘要和折叠，大数据有分页/按需加载；
- 页面不再用 `undefined`、内部 ID 或空白技术图代替用户可理解的结果。
