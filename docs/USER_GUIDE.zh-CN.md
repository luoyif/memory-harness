# Memory Harness 使用指南

## 从 Release 安装

在 GitHub Release 下载与系统匹配的 **2.2.0 完整包**，不要只下载或复制桌面
程序：

- macOS：`Memory-Harness-2.2.0-macos-universal.zip`；
- Windows x64：`Memory-Harness-2.2.0-windows-x64.zip`。

完整包内含桌面安装程序、`memoryosd` MCP/命令行伴侣、安装说明和 SHA-256。
macOS 桌面程序和命令行均包含 Intel 与 Apple Silicon 架构；Windows 为 x64。
当前公开预览包没有 Apple Developer ID、公证或 Windows Authenticode 签名，
请先核对包内哈希并按安装说明处理系统安全提示。

## 第一次打开

打开 **Memory Harness** 桌面应用即可进入唯一的管理界面。开发阶段由
`wails dev` 启动；`127.0.0.1:19777` 只用于需要 HTTP/MCP 的无界面接入，
不是另一套产品界面。

初始只有两个空间：

- **收件箱**：没有明确项目归属的来源会安全落在这里；
- **个人**：跨项目的个人身份、偏好和长期目标。

系统不会向正式数据目录填充演示数据。页面为空代表还没有导入真实内容。

首次打开默认使用 **基础模式**。顶部可以切换到 **高级模式**，选择会保存在
本机；每个主要页面也提供“查看本页用法”。基础模式只保留普通用户需要的
流程：

**新建记忆空间 → 导入原材料 → 整理本次新增内容 → 确认 AI 建议 → 处理项目待办 → 按需连接 Codex**

技术结构、运行轨迹、自动整理方式、项目收支和细粒度权限仍然完整保留，但
只在高级模式或“查看详细信息”中出现。

## 先导入第一份记忆

从左侧 **导入记忆** 开始，可使用三种方式：

- 选择一个或多个 TXT/Markdown 文件；
- 直接粘贴笔记、会议纪要或网页正文；
- 选择 ChatGPT、Claude、DeepSeek 或通用 JSON 对话导出，先预检再导入。

导入前先确认顶部的当前记忆空间。内容先保存为不可变原材料（Evidence），再进入
关键信息、会话复盘、长期记忆与生长知识的整理流程。原始对话导出保留在
本地来源档案中，平台思考块不会默认进入长期记忆。

每个空间默认“自动整理新增材料”：只处理本次新导入且尚未成功的整份对话
或文件。已经成功并且内容未变化的旧材料不会重复调用模型。如果切换成
“只保存，稍后手动处理”，导入只保存原文。

在 **记忆库** 可以点击：

- **处理新增或失败的原材料**：自动选择待处理、内容有变化或失败的材料；
- **选择原材料**：按整份对话或文件勾选，不把一份对话拆成单条消息；
- **强制重新处理全部**：只在高级模式显示，确认后重建派生结果的新版本，原始 Evidence 仍保持不变。

## 查看与理解记忆

在 **记忆总览** 先处理今天到期、已经逾期、正在进行、AI 建议和需要审核的
事项，再查看最近四周的记忆产出和最近复盘。首页的 **记忆活动日历** 按天显示
新生成的关键信息、会话复盘和长期记忆数量，并用单独标记显示当天待办；最右侧
始终是今天，不需要横向滚动。点击任意日期即可查看当天的准确数量和任务清单。
颜色只表示产出强度，页面同时提供数字和文字说明，不会只靠颜色传达状态。

首页不会把 AI 的重要程度评分直接当成“重要记忆”。如果你确认某条项目记忆值得
经常查看，可以在 **记忆库 → 项目记忆** 点击 **固定到首页**；取消固定也只改变
展示位置，不会改写记忆正文、来源或重要程度。

基础模式的 **记忆库**
只显示“原材料 → 关键信息 → 项目记忆”。高级模式才展示完整六层结构、
知识图谱和插件对象。层级数量、来源、项目归属和状态都来自当前数据。

## 建立项目空间

点击顶部项目选择器旁的 **新建记忆空间**。基础模式只需名称和可选说明；
系统会自动生成短标识、颜色、币种等默认值。高级模式可以再填写这些设置。
创建成功后会自动切换到新空间并进入首次导入。每个空间分别管理：

- Evidence、会话复盘与长期记忆；
- 当前上下文与时间事实；
- 目标、里程碑、决策和风险；
- 资金账户、收入和支出；
- 来源连接器。

跨项目检索默认关闭，只有在统一检索页明确勾选后才会发生。

## 检索与时间回看

在 **检索** 输入问题。系统会融合关键词 BM25、本地 384 维特征嵌入、时间
相关性和新近度：关键词负责精确术语，本地嵌入补足部分拼写、词形和局部文本
相似情况。这个向量完全在本机生成，不下载模型、不上传内容，也不需要单独的
向量数据库；它不是云端语义 Embedding 模型。除了普通当前召回，还可以填写
“时间锚点”回答“当时什么最相关”，并选择是否包含已被取代/过期的历史。
结果显示记录类型、项目、状态、有效区间、时间关系和时间相关度；时间接近只
表示上下文相关，不代表因果。高影响结论应继续点开 Evidence 原文核对。

在 **时间脉络** 中可以：

- 查看事实、目标、里程碑、决策、Episode、Memory、Run、Evidence 等统一时间线；
- 选择历史锚点，查看当时 active / upcoming / overdue / historical 的内容；
- 显示被新事实取代的完整历史；
- 查看两个事件/任务之间的 `overlaps / contains / during / near_in_time` 时间相关性、强度和理由。

纠正事实不会删除过去，而是用新事实明确取代旧事实。

## 项目工作台与待办

项目工作台首先显示 **我的待办**：已逾期、今天到期、正在处理、AI 建议和
需要我审核。人工新建的待办直接进入正式清单；AI 从目标或会话中识别出的
行动项只能进入“AI 建议待办”。只有点击 **加入待办** 后才成为正式任务。
AI 和 MCP Agent 都不能替 Owner 完成这一步。

待办支持开始、完成、重新打开和忽略建议，始终保留人工或 AI 来源以及原始
Evidence 引用。核心上下文和决策默认只显示三行摘要，点击“查看全文”再从
右侧抽屉阅读完整内容和来源。

项目目标、决策、风险与核心上下文仍可单独新增。在高级模式还可以设置：

- **自动整理新增材料**，或 **只保存，稍后手动处理**；
- 打开“自定义整理方式”和具体步骤编辑器；
- 查看可选的 **项目收支（可选）**。基础模式不会显示项目资金。

- 完成目标/里程碑、缓解风险会更新状态并保留历史；
- 资金记录只能作废，不能无痕删除；
- 不同币种分别统计，不自动套用未知汇率；
- 核心上下文的“AI 最多读取多少内容”在高级模式设置，避免上下文无限膨胀。

## 多 AI 协作

**多 AI 协作**不是自动启动多个模型。Memory Harness 只管理身份、项目权限、
共享范围、冲突和长期记忆，外部 AI 需要各自连接并主动工作。

1. 在“连接与健康”创建并连接不同 AI，勾选“参与多 AI 协作”；
2. 创建协作任务，选择直接参与的 AI；
3. 每个 AI 的私密草稿只对作者可见，只有主动提交的内容才按指定对象共享；
4. 接收者不能转发别人的内容；共享过期后立即失效；
5. 多个 AI 意见冲突时不会自动覆盖，由 Owner 审核；
6. 任务内容必须由 Owner 选择并审核，才能进入长期项目记忆。

Codex 对应的 MCP 工具可以列出参与任务、读写自己的私密草稿、读取直接共享
内容、提交共享内容、调整自己内容的共享对象，以及提出退出任务申请。完整
工具和权限表见 `docs/MCP.md`。

## 知识产品

**知识产品** 把长期记忆整理成人更容易阅读和继续维护的对象，包括 Project Brief、Report、Diary、个人能力画像、个人档案、决策日志和风险报告。Project Brief 随新材料的项目沉淀自动生长，也可以点击“手动生成 / 刷新项目简报”立即刷新；两种方式都不会重跑历史 Evidence。人工新建产品可以先套用对应结构模板，保存时会先把正文保存成不可变 Evidence，再创建产品对象。

人工修改不会覆盖旧内容，而是新增 Revision。可以锁定 `title / summary / body` 中任意字段；后续自动重建仍会生成新 Revision，但不会改写锁定的人工作品。

## 复核与能力资产

**能力资产工坊** 把可复用程序性记忆分成 Prompt、Skill、Rule、Constraint、Procedure、Tool Recipe 和 MCP 七类。第一轮只发现候选并定类；点击“按模板二次沉淀”后，系统才按该类型的独立 V4 模板补齐触发条件、输入输出、步骤、边界与验收。可以筛选最近 7 天、最近 30 天或手动勾选；默认增量模式会跳过来源未变化的候选，“重新检查当前范围”才会再次调用模型。模型不可用时只生成不能激活的待补齐骨架。信号不足时保持“待人工分类”，不会强行猜测，也不会重跑或改写 Evidence。

Agent 如果拥有 `memory.propose`，最多只能提出 V4 或兼容 V3 能力资产的新 Revision 候选；它不能批准自己的修改，也不能绕过本地 Owner 会话。

## 模型与高级构建

**连接与健康** 支持三种真正独立的调用方式：OpenAI Responses、
OpenAI-compatible Chat Completions 和 Anthropic Messages。可以直接选择
OpenAI、Anthropic / Claude、DeepSeek、OpenCode Go 或兼容服务预设，也可以
填写未收录的模型。没有模型时，本地规则仍能完成确定性沉淀；配置模型后，
模型输出仍需结构校验和审核策略。

第一次连接建议按以下顺序操作：

1. 点击“添加模型”，选择常用接入；
2. 选择或填写模型名。对于 OpenCode Go，系统会按模型自动匹配 Responses、
   Chat Completions 或 Messages；
3. 输入密钥并保存。密钥只写入系统钥匙串，不会显示在提供方列表；
4. 点击“测试”，读取该账号当前可见的 `/models` 列表；
5. 只有测试通过后再点击“启用”。

内置模型目录是帮助选择接口的知识快照，不代表账号一定拥有该模型。提供商
可能随时新增、下线或改名；界面会显示目录更新时间，实际可用性始终以
“测试连接”的即时结果为准。OpenCode Go 尤其不能把所有模型都当成同一个
OpenAI 兼容接口。

长录音会按句子边界分段提炼，并过滤寒暄、重复、语气词、残句和指代不明的
内容。旧录音如曾经产生大量低质量知识点，可在 **记忆库 → 会话复盘** 中
选择 **用当前模型重新沉淀**；原始 Evidence 不会删除，只有可重建的派生内容
会被替换。完成后可分别检查生长知识正文、能力资产、知识图谱、项目工作台
的自动上下文，以及运行记录中的六阶段轨迹。

多人录音请在会话卡片点击 **说话人与人物**。只有当整份语料中的第一人称
始终属于同一个人时，才填写“整份语料中的我是谁”；不同参与者都说过“我”
时应留空，并逐行填写重要人物。未确认的“我、用户、讲者、speaker”等内容
会显示为候选和“主体待确认”，不会默认映射为 Owner、进入可信知识图谱或
作为已生效事实提供给 Agent。保存人物资料后可以立即用当前模型重新沉淀。

大多数用户不需要编辑记忆策略。策略工坊、流程编辑器和插件中心集中在默认收起的 **高级构建** 中：

- Blueprint 的 Growth Track 已真正控制默认 Pipeline 的物化层；关闭 Agent Asset / Living 等角色会改变实际产物，并写入 Run trace；
- Pipeline Studio 的 **Dry Run** 是零写入预演：纯 JSON 阶段在内存计算，模型/业务写入只显示计划；
- 已完成 Run 若保存了阶段快照，可在 Run Explorer 选择 **从此阶段分支**；旧 Run 缺快照时会要求整次 Retry；
- Plugin Center 会先展示对象、Revision、Run、Pipeline/Blueprint 和项目依赖影响；只有安全时才能退役。退役不会删除历史，重装同内容哈希版本后可以恢复执行。

## 健康、备份与恢复

**系统健康** 页面会检查 Ledger、项目关联、六层记忆、统一 FTS 索引和本地
嵌入投影；向量数量、算法、维度或载荷不一致都会显示为失败。

```bash
./bin/memoryosd export --output memoryos-backup.tar.gz
./bin/memoryosd restore --input memoryos-backup.tar.gz --home /path/to/empty-folder
```

恢复目标必须为空。恢复会校验清单、文件大小和 SHA-256，并自动重建派生检索索引；不会覆盖现有数据目录。
